01「实现跳表」到底是在实现什么

你写了三件事，跑出了 PASS，但感觉不知道自己在造什么。原因是：跳表这个概念听起来像个「数据结构」，落到代码里其实是一组必须永远成立的约束。

整个跳表约 200 行，剥掉注释和辅助函数，真正的内容是三条不变量和三个操作。你写错任何一行代码，本质都是破坏了其中某一条不变量。

不变量含义破坏后什么症状
① L0 全量有序最底层那条链表包含全部节点，且 key 严格升序数据丢失、遍历漏记录、范围查询错
② 指针只能向上指节点 next[lv] 指向的目标，其层数必须 > lv查找到一半读越界 → 段错误（或读到垃圾 key）
③ level_ 是真实上限level_ = 当前最高层数，所有节点层数 ≤ level_ ≤ kMaxLevel从空层开始查 → 白走几层，或新节点升不到该升的层

「实现跳表」＝ 写出三个操作，并且保证每个操作跑完之后，这三条不变量依然成立。

操作做什么维护了哪条不变量
Find找到「最后一个 key < target 的节点」，顺便判断 target 在不在不改结构，只读
Insert先 Find 记下每层前驱 prevs[]，再逐层插指针①②③ 全都要维护（层数变高时要更新 level_）
Delete不真删，把记录改成 type = kDelete 的墓碑①（节点还在，只是值变了）
关键的一句话

Insert 和 Delete 都建在 Find 之上。Find 返回的那个「最后一个 key < target」，正好就是新节点要挂上去的前驱。所以明天你写 Insert，会发现它 90% 的代码和 Find 一模一样，只是把每层走过的 p 存进 prevs[] 数组。

02查询逻辑

整段查询只有一条决策规则，两个循环只是把这条规则用在不同的层上：

Node* p = head_;
for (int lv = level_ - 1; lv >= 0; --lv) {              // 外层：从上往下，一层一层降
  while (p->next[lv] != nullptr &&
         p->next[lv]->key < key) {                      // 内层：右边还更小，就一直往前跳
    p = p->next[lv];
  }
}
// 走到这里，lv 已经降到 -1，p 是「最后一个 key < target」的节点
Node* cand = p->next[0];
if (cand != nullptr && cand->key == key) return 找到;

决策规则（只有这一条）：

规则

看 p->next[lv] 那个节点：key 比目标小 → 跳过去，p = 它；否则（比目标大、或者根本没有）→ 降一层，p 不动。

三个容易想歪的地方：

  • 为什么是「严格小于」而不是「小于等于」？因为要找的是「最后一个 < target」的节点，这样它后面的那个才有可能是 target 本身。写成 <= 会直接跳过目标。
  • 降层时 p 不动。降层只是换一个 next 下标去看更近的地方，节点本身没变。这是最容易画错的地方——很多人以为降层是「退回去」。
  • 循环结束后还要验证一步。因为循环条件是「小于」，所以 p 肯定不是 target，但 p->next[0] 可能是。这一步不做，就会把「不存在」当成「找到前驱」。

复杂度：p 在整个过程中只向右移动、从不回头，所以总移动次数 ≤ 层数 + 横向次数。层数是 O(log n)，每层横向期望 O(1)，合计 O(log n)。

    怎么读这个动画

    查询 i 的轨迹：页面上共 8 步 = 7 次比较 + 1 次收尾检查。p 只经过 4 个位置：head → f → g → h。第一跳从 head 直接落到 f，一步跳过了 a b c d e 五个节点——这就是「多层索引」省下的时间。到了 L0 之后才一格一格挪，因为下面的节点太密，上层索引帮不上忙。

    插入 hh（2 层）的轨迹：前半段和查询完全一样，唯一区别是每次降层时多记一笔 prevs[lv] = p。走完之后，prevs[0] 和 prevs[1] 就是新节点在 L0、L1 上前驱。最后一步做的是纯粹的四次指针赋值：

    // 对 i = 0 .. 新节点层数-1：
n->next[i]          = prevs[i]->next[i];   // ① 新节点接管前驱原来的后继
prevs[i]->next[i]   = n;                  // ② 前驱改为指向新节点

    这两行的顺序不能反。如果先执行 ②，prevs[i]->next[i] 已经变成 n 了，第 ① 行读到的就是自己，新节点指向自己 → 链表断掉，后面的查询死循环。这类错误在双链表里叫「先断后接」，跳表的插入是同一个道理。

    06自测 4 题

    1. 查询时为什么判断用 < 而不用 <=？换成 <= 会在哪种 key 上出错？

    因为要停在「最后一个 严格小于 target」的节点上，它右边才有可能是 target。用 <= 的话，查到 target 本身时会继续往前跳过它，最后停在 target 之后一个节点上，然后 p->next[0] 已经越过目标，永远返回「不存在」。所有命中查询都会失败。

    2. 插入时 prevs[i] 存的是什么？为什么要每层存一个，而不是只存 L0 的？

    存的是「第 i 层上，最后一个 key 小于新 key 的节点」。因为新节点有若干层，每一层的邻居都不一样——同一层的前驱在 L1 可能是 f，在 L0 可能是 h。只存 L0 的话，往上那几层找不到该插在哪，要么插错位置破坏有序性，要么放弃上层索引。

    3. 插入那两行赋值，为什么必须先 n->next[i] = prevs[i]->next[i] 再 prevs[i]->next[i] = n？

    反过来的话，第一步就把 prevs[i]->next[i] 改成了 n，第二步再执行 n->next[i] = prevs[i]->next[i] 读到的就是 n 自己 → 新节点指向自己，链表在这里断成一个自环。后续查找到这就死循环。本质是覆盖之前必须先把旧值读出来，和析构时「先存 next 再 delete」是同一种错误。

    4. 如果 RandomLevel() 永远返回 1，程序会崩吗？会慢多少？怎么发现？

    不会崩，也不会功能出错——数据全在 L0，查询照常命中。但失去了多层索引，查询退化为遍历单链表：n 条数据从 O(log n) 变成 O(n)。10 万条大概慢 20~30 倍。发现方式只有统计分布：测出的均值会贴在 1.0 上，而不是 2.0。任何断言都抓不住它，因为每一步的结果都是「正确」的。
