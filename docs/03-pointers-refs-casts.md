# 指针、引用、类型转换 —— 一次讲透

> 这份文档解决你连续几天卡住的**同一层**问题：指针和内存模型。
> 不是 C++ 语法问题，是「脑中要能画出地址」的问题。
> 全文用的例子全部来自你写的 `record.h`，不是玩具代码。

---

## 0. 先说清楚一件事

你以为的困惑是「`*` 和 `&` 是什么意思」。

实际上不是。`*` 和 `&` 每个都有**三个完全不同的身份**，它们长得一样，干的活毫无关系。你每次看不懂，几乎都是因为把「声明」当成了「运算」，或者反过来。

所以第一步不是背含义，是**学会判断当前处于哪种语境**。

---

## 1. `&` 的三个身份

| 出现的位置 | 叫什么 | 干什么 | 例子 |
|---|---|---|---|
| **类型名后面**（声明时） | 引用声明 | 起个别名，不复制数据 | `int& r = x;` |
| **变量名前面**（使用时） | 取地址 | 问「它住在内存的哪个门牌号」 | `&v` |
| **两个变量中间** | 按位与 | 位运算，跟指针无关 | `a & b` |

```cpp
int  x = 5;
int& r = x;       // ① 声明：r 是 x 的别名，r 和 x 是同一块内存的两个名字
int* q = &x;      // ② 取地址：q 里存的是 x 的门牌号
int  c = x & 0xff; // ③ 按位与
```

**判断规则（记住这一条就够了）：**

> 看 `&` **前面有没有类型名**。
> 有 → 是声明（①）。
> 没有 → 是运算（②取地址 或 ③按位与，看右边是变量还是数字）。

---

## 2. `*` 的三个身份

| 出现的位置 | 叫什么 | 干什么 | 例子 |
|---|---|---|---|
| **类型名后面**（声明时） | 指针声明 | 声明「这个变量存的是门牌号」 | `int* p;` `const char* p;` |
| **指针名前面**（使用时） | 解引用 | 顺着门牌号去把东西拿出来 | `*p` |
| **两个数字中间** | 乘法 | 算术 | `a * b` |

**同一条判断规则：**

> 看 `*` **前面有没有类型名**。有 → 声明；没有 → 运算。

```cpp
int  x  = 5;
int* p  = &x;    // 左边 int* 是声明（存地址），右边 &x 是取地址
int  y  = *p;    // *p 前面没有类型名 → 解引用 → y = 5
```

### ⚠️ 最容易误解的一句

```cpp
const char* p = buf.data();
```

这里的 `*` **不是解引用，是声明的一部分**。整句读法是：

> 「`p` 是一个变量，它的类型是 `const char*`，也就是**存着一个地址，那个地址指向一串只读的 char**。」

它跟字符串、跟解引用、跟指针运算，此刻**一点关系都没有**。它只是在说 `p` 的类型。

下一行 `*p` 才是解引用 —— 因为前面没类型名了。

## 3. 为什么游标必须是 `char*`（这个问题的真正答案）

你的 `Decode` 里：

```cpp
const char* p     = buf.data();
const char* limit = buf.data() + buf.size();
```

**`char` 是 C++ 里唯一保证「大小正好 1 字节」的类型。**

（`int` 可能是 2/4/8 字节，`long` 在 Windows 是 4 字节、Linux 是 8 字节 —— 都不保证。）

游标要做的事是「往后挪 1 个字节」「往后挪 n 个字节」，所以它的单位必须是 1 字节。**只有 `char` 能做到。**

如果换成 `int*`：

```cpp
int* p = ...;
p + 4;      // ❌ 不是走 4 字节，是走 4 × sizeof(int) = 16 字节
```

指针加法是按「元素个数」算的，不是按字节算。`char*` 的元素大小恰好是 1，所以 `p + 4` 才等于「走 4 个字节」。**这不是巧合，是选 char 的唯一理由。**

`void*` 也不行：它不能解引用，而且标准不允许对它做指针算术。

## 4. 三层地址链：`**` 到底在干什么

先看 `GetFixed32` 的签名：

```cpp
inline uint32_t GetFixed32(const char** p, const char* limit)
```

**为什么是 `**`？** 因为它要**修改调用者的游标**。

C++ 函数传参默认是**复制**。如果签名叫 `const char* p`，函数里 `p += 4` 改的只是副本，`Decode` 里的 `p` 一根毛都不会动。要让函数改到外面那个变量，唯一办法是**把外面那个变量的地址传进来** —— 而「一个 `const char*` 变量的地址」，类型就是 `const char**`。

画出来是这样（这就是最上面那张图）：

```
┌──────────────────┐      ┌──────────────────┐      ┌─────────────────┐
│ GetFixed32 的 p   │  *p  │   Decode 的 p     │ **p  │   buf 的字节     │
│ 类型 const char** │─────▶│ 类型 const char*  │─────▶│ 0x2000 起 19B   │
│ 值   0x7ffd1000   │      │ 值   0x2001       │      │ 01 04 00 00 ... │
└──────────────────┘      └──────────────────┘      └─────────────────┘
   存着「p 的地址」           存着「buf 里的位置」        真正的数据
```

**每一层 `*` 剥掉一层盒子：**

| 表达式 | 类型 | 值 | 含义 |
|---|---|---|---|
| `p` | `const char**` | `0x7ffd1000` | Decode 那个 p 变量住在哪 |
| `*p` | `const char*` | `0x2001` | 游标现在指向 buf 的第几个字节 |
| `**p` | `char` | `0x04` | 那个字节本身 —— 也就是 klen = 4 |

**关键的一句：**

```cpp
*p += 4;
```

- 左边 `*p` 解引用 → 拿到「Decode 的 p」这个盒子
- `+= 4` 改的是**这个盒子里的值**
- 因为盒子的地址是外面那个变量的地址，所以**外面的 `p` 真的动了**

这就是 `**` 存在的全部理由。没有它，函数改不动调用者的游标。

## 5. `static_cast` 是什么

### 5.1 一句话本质

> `static_cast<T>(x)` **运行时不产生任何机器指令**。它只做一件事：**告诉编译器「我知道我在干什么，你闭嘴」**。

它不转换、不搬运、不检查。它只是**解除编译器的抱怨**。

### 5.2 为什么不能直接写 `(T)x`（C 风格转换）

```cpp
char c = (char)record.type;      // 能过，但很危险
char c = static_cast<char>(record.type);  // 能过，且安全
```

C 风格转换的问题是**它会尝试所有类型的转换**，包括最危险的 `reinterpret_cast`（把内存原样重新解释）。一旦你写错，编译器不报错，程序在运行时给你一堆垃圾。

`static_cast` 只允许「编译器认为有意义」的转换。写错了直接编译失败。

| 转换 | 用途 | 安全性 |
|---|---|---|
| `static_cast` | 数值/枚举/指针上下转 | 编译期检查，**你该用的就是这个** |
| `dynamic_cast` | 多态类型的运行时检查 | 有运行时开销，要 RTTI |
| `const_cast` | 去掉 `const` | 危险，改只读内存是 UB |
| `reinterpret_cast` | 把内存原样重新解释 | 最危险，几乎不该用 |

### 5.3 你代码里的四处，逐条讲

#### ① `static_cast<char>(record.type)`

```cpp
out.push_back(static_cast<char>(record.type));
```

`record.type` 的类型是 `RecordType`（`enum class`）。

**`enum class` 故意设计成不能隐式转成整数。** 所以必须显式转。这也是它比老式 `enum` 安全的地方：

```cpp
enum       Old { kPut = 1 };   // 老式：能偷偷变成 int，还能跟别的 enum 混着比
enum class New { kPut = 1 };   // 新式：必须 static_cast，不会悄悄变成 int
```

老式 enum 的毛病：两个不同 enum 的值能直接比较（都是 int），命名还会污染外层作用域。`enum class` 把这两个坑都堵上了，**代价就是你每次都得写 static_cast**。这笔交易是划算的。

#### ② `static_cast<uint32_t>(record.key.size())`

```cpp
PutFixed32(&out, static_cast<uint32_t>(record.key.size()));
```

`size()` 返回 `size_t`，在 64 位系统上是 **8 字节无符号**。而 `PutFixed32` 要 `uint32_t`，**4 字节**。

这是**窄化转换**：8 字节塞进 4 字节，高位会被丢掉。编译器默认会警告（`-Wconversion`）。

`static_cast` 在这里的意思是：

> 「我知道我在丢高位。因为 key 的长度不可能超过 4GB，丢掉的位一定是 0。」

**这一处是你自己加的，比我原来的隐式转换更严谨 —— 记住这一点。** 文件格式里凡是「宽度固定」的地方，都应该显式写明你知道在窄化。

#### ③ `static_cast<RecordType>(*p)`

```cpp
out->type = static_cast<RecordType>(*p);
```

`*p` 是 `char`（一个整数，值是 1 或 2）。要变回 `RecordType`，方向反过来，还是得显式转。

**注意这里没有校验 `*p` 是不是合法值。** 如果文件被篡改成 `0x63`，`out->type` 就是一个非法的 `RecordType` —— 后面 `if (type == kDelete)` 会静默走错分支。这是 10-23 要补的「错误处理」内容，先记着。

#### ④ `static_cast<size_t>(p - buf.data())`

```cpp
*consumed = static_cast<size_t>(p - buf.data());
```

两个指针相减，结果类型是 `ptrdiff_t` —— **有符号**（因为可能是负的）。
`consumed` 是 `size_t*` —— **无符号**。

有符号转无符号，同样需要显式说明。这里逻辑上不可能为负（`p` 只会往后走），所以转换是安全的。

## 6. 指针减法为什么等于字节数

```cpp
p - buf.data()
```

指针相减的规则是：**结果 = 两个地址之间隔了几个元素**，不是隔了几个字节。

对 `char*` 来说，一个元素就是 1 字节，所以「隔了几个元素」= 「隔了几个字节」。**这又是选 char 带来的便利。**

如果是 `int*`，`p - q = 3` 意味着隔了 12 字节。

## 7. 自测题（先别看答案，写在纸上）

1. `const char* p` 里的 `*` 是解引用还是声明？依据是什么？
2. `uint32_t v; std::memcpy(&v, *p, 4);` —— 这两行里两个 `&`/`*` 各是什么身份？
3. 如果 `GetFixed32` 的签名改成 `uint32_t GetFixed32(const char* p, const char* limit)`（少一个星），`Decode` 会发生什么？为什么？
4. `p += 4` 和 `*p += 4` 差在哪？各改的是哪个盒子？
5. 为什么 `PutFixed32` 收的是 `std::string*` 而不是 `std::string`？

<details>
<summary>答案</summary>

1. **声明**。因为 `*` 前面紧挨着类型名 `const char`。判断只看这一点，不看别的。
2. `&v` 是**取地址**（`memcpy` 需要一个「往哪写」的地址）；`*p` 是**解引用**（拿到 `p` 指向的那个字节，作为「从哪读」的起始地址）。
3. `Decode` 里 `p` **永远不会前进**。因为传进去的是副本，函数里 `*p += 4` 改的是副本。结果：读到第二段时游标还在原地，`klen` 会反复读到同一个值，最终 `consumed` 恒为 1 或直接越界返回 false。**这就是「要改调用者的变量，就得传它的地址」的活教材。**
4. `p += 4` 改的是**游标变量本身**（指针往后挪 4 字节，指向新的位置）；`*p += 4` 改的是**游标指向的那个字节的值**（数据被改了，游标没动）。这是两个完全不同的事，只差一个 `*`。
5. 因为 `PutFixed32` 要往 `dst` **末尾追加字节**，必须改到调用者那个 string 对象。传值会复制一份，改完就扔了。传指针（或引用）才能改到本体。

</details>

## 8. 建议的练习顺序

**不要一上来就读《C++ Primer》第 2 章。** 那本书讲得太全，你会淹没在细节里。

按这个顺序，每步 20 分钟，一天一步：

1. **今天**：把上面 5 道自测题写在纸上，写完再看答案。做错的题，回对应小节重读。
2. **明天**：在 `src/scratch.cpp` 里写一个 `swap(int* a, int* b)`，再用 `swap(int& a, int& b)` 写一遍。两次都能改到调用者的变量 —— 体会「指针」和「引用」是同一个东西的两种写法。
3. **后天**：在 `scratch.cpp` 里**故意**把 `GetFixed32` 的签名改成单星号版本，跑一遍 `demo_record`，亲眼看它怎么坏。**见过坏的样子，才认得好的样子。**
4. **第四天**：用 `printf("%p", (void*)p)` 把 `Decode` 里每一步的 `p` 打出来，看着它从 `0x...00` 走到 `0x...04`、`0x...08`、`0x...13`。**让地址变成你能看见的数字。**

第 4 步做完，指针这一层就算过关了。它不靠理解，靠**看见**。

## 9. 一句话总结

| 概念 | 一句话 |
|---|---|
| `*` / `&` | 前面有类型名 = 声明；没有 = 运算 |
| `char*` | 唯一保证 1 字节的类型，所以游标只能用它 |
| `**` | 因为函数要改调用者的变量，只能传它的地址 |
| `static_cast` | 运行时不干事，只是让编译器闭嘴；写出来 = 声明「我知道我在转换」 |
| `p - q` | 隔了几个**元素**；对 `char*` 才等于字节数 |
