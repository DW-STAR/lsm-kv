# 核心认知：为什么是"只追加"

> 这份文档是给你自己复习用的。看不懂的时候回来读一遍。

---

## 一句话

**这个存储引擎的全部设计，都源自一个约束：只许往末尾写，不许回头改。**

---

## 为什么定这么个奇怪的规矩

想象一本一万页的笔记本。你要改第 1 页某一行 —— 得先翻到第 1 页，找到那一行，划掉，再写新的。

这个动作用在硬盘上叫**随机写**，很慢。机械硬盘尤其慢，因为磁头要来回移动。

反过来，**一直往本子末尾写**，永远不用找位置，这叫**顺序写**。

**顺序写比随机写快几十倍。** 全部的收益都在这里。

---

## 三条规则

| 操作 | 怎么做 |
|---|---|
| **写** | 往末尾加一条，不管 key 是不是已经存在 |
| **读** | 从后往前翻，第一条匹配的 key 就是最新的 |
| **删** | 不擦掉旧的，而是**再写一条"墓碑"**（一条特殊标记的记录） |

**"后写的赢"这件事，不是在写的时候实现的，是在读的时候实现的** —— 靠"从后往前找"这个动作。

---

## 五个术语的翻译

| 你听到的 | 其实是在说 |
|---|---|
| **WAL** | 流水账本 —— 先记账再干活，断电了照着账恢复 |
| **MemTable** | 手边的小本子 —— 数据在内存里，写得快 |
| **SSTable** | 归档的大本子 —— 小本写满就存到磁盘，排好序 |
| **Bloom Filter** | 书脊上的标签 —— 说没有就没有，跳过不用翻 |
| **Compaction** | 定期合并 —— 小本并成大本，顺手清掉作废的 |

**这五个没有一个是"新概念"。** 它们是"用笔记本记东西"这个动作的五个环节，只是各起了一个英文名。

---

## 演进链：每一步都是被逼出来的

```
只追加日志  →  数据在内存，关机就没了
                    ↓ 所以要落盘
                  WAL
                    ↓ 但日志无限变长，读一次要扫全部
             MemTable + SSTable
                    ↓ 但文件多了，查一次要翻好几遍
               Bloom Filter
                    ↓ 但文件越积越多，磁盘被撑爆
                Compaction
```

**没有一个是发明出来的**，全是「上一个方案撞墙了，只能这么解」。

面试官问"为什么要 Bloom Filter"，答"它能回答'这个文件里有没有'，省掉一次磁盘读"是理解；答"因为 LevelDB 里有"是背。

## 你已经亲手验证过的一件事

`Delete` 写的是 `Append(key, kTombstone)` —— 追加一条墓碑。

结果是：**你删掉一条数据，日志里的记录数反而 +1。**

这在真实系统里也一样。因为"只追加"的世界里，你没法把任何东西擦掉 —— 你只能**声明它作废**。

**这就是为什么磁盘迟早会被撑爆**，也是 Compaction 存在的全部理由。

## 编码的本质（你问过："编码的本质到底是什么"）

**不是"转成字节"。是"用字节把结构重新描述一遍"。**

推三步就通了：

1. **硬盘只会搬字节。** 它不知道你内存里原来有类型、有长度、有几个字段——这些它一概不记得。
2. **所以要穿过这道窄门，结构必须你自己写进去。** 一个字节记类型、四个字节记长度、按固定顺序排字段——**这些全是"结构"的替身**。
3. **读的人照着这份描述，就能重建出一模一样的对象。**

一句话：

> **编码 = 给未来写一份足够精确的说明书，让对方能原样重建。**
> 不是"转换"，是"描述"。

**检验标准只有一条：能不能原样还原。**

所以编码写对了没有，Encode 自己说了不算 —— **必须由 Decode 来证明。** 这就是下一步要写 Decode 的原因，不是为了"对称好看"。

---

## 两个不习惯的东西，都不是你的问题

**十六进制**：1 个字节 = 8 位 = **2 个十六进制位**，一一对应，不多不少。`6e` 就是"这个字节是 110"，二进制写作 `01101110` 但没人愿意看 8 个 0 和 1。**它纯粹是"给人看字节"的眼镜，没有计算含义。** 不习惯只是没戴过。

**`std::string` 装字节**：教材里 string 只装文本，所以你没见过 —— 你现在见的不是教材例子的用法。正经类型是 `std::vector<char>`。项目里用 string 是工程习惯（`append` 方便、能直接喂给 `write()`，LevelDB 也这么干）。
**唯一的坑**：string 里可以合法装 `\0`，`size()` 才是真长度。**永远别对它用 `strlen` / `printf("%s")` / `c_str()`** —— 那些遇到 `\0` 就截断了。详细见 `02-cpp-basics.md` 第 16 条。
