# 有思路，但写不出代码 —— 翻译手册

> 这个文件解决的是一个很具体的问题：
> **「我知道要干什么，但不知道用什么符号表达。」**
>
> 这不是能力问题。C++ 里 95% 的常见意图都有现成的构造，
> 你缺的不是逻辑，是**索引**——知道"我想要 X，语言里那个东西叫什么"。
>
> 每次卡住，先来这里查；查不到，用第 5 节的方法问。

---

## 0. 先看清楚卡在哪一层

写代码其实是三件不同的事，同时做会互相打架：

| 层 | 你要回答的问题 | 靠什么 |
|---|---|---|
| **① 逻辑** | 这一步要干什么？ | 人话，不用写代码 |
| **② 翻译** | 这件事用哪个构造表达？ | **这张表** |
| **③ 语法细节** | 分号、括号、类型对不对？ | 编译器和报错 |

**大部分"不会写"发生在 ② 层，但人误以为是 ① 层，于是回去重新想逻辑——白绕一圈。**

所以卡住时第一个动作是问自己：**「我是不知道要干什么，还是不知道用哪个词？」**

- 不知道要干什么 → 回去用中文写步骤
- 不知道用哪个词 → 往下查表

---

## 1. 三步法：从人话到代码

### 第一步：用中文写出步骤，一句一行

不许出现代码。例如"把文件读进内存"：

```
1. 打开文件
2. 问一下文件有多大
3. 造一个那么大的空串
4. 一次读进去
5. 关掉
```

**这一步写完，你就已经完成了 70%。** 剩下的全是查表。

### 第二步：每句问三个问题，答案就是语言构造

| 问自己 | 答案是 |
|---|---|
| 这一步需要**记住**什么？ | 一个**变量** |
| 这一步要**重复**吗？ | 一个**循环**（`while` / `for`） |
| 这一步**可能失败**吗？ | 一个 **if** + `return` / `break` |
| 这一步要**留下结果**吗？ | 一次 `push_back` / `append` / 赋值 |

例：

```
2. 问一下文件有多大     → 需要记住一个数 → size_t n
4. 一次读进去           → 需要记住一段字节 → std::string
一直读直到读完           → 重复 → while
读坏了就停               → 可能失败 → if (!...) break
```

**变量和循环不是"高级技巧"，它们是这三问的直接产物。** 你缺的一直是这个推导过程。

### 第三步：逐行翻译，翻不出来的那行去查表

翻不出来的地方**标记出来**，不要停在那里硬想。全部翻完再回头查——因为查一个词的成本远低于卡在中间十分钟。

## 2. 意图 → 构造 对照表

按"我想干什么"查，不按语法查。

### 2.1 记住一个东西

| 我想…… | 写法 |
|---|---|
| 记住一个整数，从 0 开始 | `size_t offset = 0;` |
| 记住一个整数，之后可能改 | `size_t offset = 0;` 然后 `offset += n;` |
| 记住一段字节 | `std::string buf;` |
| 记住"成功还是失败" | `bool ok = false;` |
| 记住"读了多少" | `size_t consumed = 0;` |
| 一个常量字符串 | `const char* const kPath = "wal.log";` |

### 2.2 重复

| 我想…… | 写法 |
|---|---|
| 只要条件成立就继续 | `while (条件) { ... }` |
| 按次数循环 | `for (size_t i = 0; i < n; ++i) { ... }` |
| 至少执行一次 | `do { ... } while (条件);` |
| 从后往前遍历 | `for (auto it = v.rbegin(); it != v.rend(); ++it)` |

### 2.3 提前跳出

| 我想…… | 写法 |
|---|---|
| 跳出整个循环 | `break;` |
| 跳过这一轮，进入下一轮 | `continue;` |
| 直接结束整个函数 | `return false;`（或 `return true;`） |

### 2.4 判断

| 我想…… | 写法 |
|---|---|
| 剩下的够不够长 | `if (p + n > limit)` |
| 两个是不是一样 | `if (a == b)` |
| 是不是不一样 | `if (a != b)` |
| 条件不成立 | `if (!ok)` |
| 两个都要成立 | `a && b` |
| 任一成立 | `a \|\| b` |
| 二选一取值 | `x = 条件 ? 值A : 值B` |

### 2.5 往容器里放东西

| 我想…… | 写法 |
|---|---|
| 往字符串末尾塞 1 个字节 | `s.push_back(c)` |
| 往字符串末尾塞 n 个字节 | `s.append(p, n)` |
| 往字符串末尾接另一个字符串 | `s.append(other)` |
| 往 vector 末尾加一条 | `v.emplace_back(a, b)` |
| 往 vector 末尾加一个现成对象 | `v.push_back(obj)` |

### 2.6 从容器里拿东西

| 我想…… | 写法 |
|---|---|
| 从某处拷 n 个字节出来 | `s.assign(p, n)` |
| 取一段子串（复制） | `s.substr(pos, n)` |
| 取第 i 个 | `v[i]` |
| 取最后一个 | `v.back()` |
| 一共有多少 | `s.size()` / `v.size()` |
| 是不是空的 | `s.empty()` |

### 2.7 索引 vs 长度（最容易混）

| 概念 | 含义 | 例 |
|---|---|---|
| **起点 / 偏移** | "从第几个字节开始" | `offset = 19` |
| **长度 / 数量** | "占几个字节" | `consumed = 13` |
| 结尾位置 | 起点 + 长度 | `offset + consumed = 32` |

**规律：起点是"第几个"，长度是"几个"。混了就会差一位。**

## 3. 反向翻译：先看你**已经写对**的代码

比自己写更有用的是：把自己写对的东西翻译回人话，建立"符号 ↔ 意图"的对应。

### 例 1（你写的 `Get`）

```cpp
for (auto it = entries_.rbegin(); it != entries_.rend(); ++it) {
  if (it->first != key) { continue; }
  if (it->second == kTombstone) { return false; }
  *value = it->second;
  return true;
}
```

人话：

> 从**最后一条**往前一条条看；
> key 不对就**跳过**看上一条；
> 如果碰到的是墓碑，就当它**不存在**，返回失败；
> 否则把 value **抄出去**，返回成功。

**注意这里每一句人话，都精确对应一行代码。** 这就是"翻译"完成的样子。

### 例 2（你写的 `Encode`）

```cpp
out.push_back(static_cast<char>(record.type));
```

人话：**把"这条是存还是删"，压成一个字节，塞到末尾。**

`push_back` = 塞到末尾。`static_cast<char>` = 压成一个字节。

### 例 3（你写的 `Decode`）

```cpp
out->key.assign(p, klen);
p += klen;
```

人话：**从 p 这个位置拷 klen 个字节当 key；然后把游标往后挪 klen。**

注意这是**两步**：`assign` 只拷贝，**不挪游标**；挪游标得你自己写。这就是为什么这两行必须成对出现。

## 4. 一个反直觉但极其有效的建议

**先写"结构对但编译不过"的代码。**

大部分人卡住，是因为想一次写出"能编译的、正确的"代码。这是两个目标，同时追会互相拖累。

正确顺序：

1. **先把结构写出来**，函数名、变量名、循环、if 都写，哪怕函数名是编的、类型是猜的
2. 编译，**让编译器告诉你哪一行不对**
3. 逐条改

编译器是个不知疲倦的审稿人，你不需要在脑子里模拟它。

> 你现在的做法是"脑子里先跑一遍编译器"，跑不动就停住了。
> **把这一步外包给编译器。**

## 5. 卡住时的正确提问方式

**这种问法是合法的、也是最高效的：**

> 「我想做到 X（用一句人话说清楚），C++ 里该用什么？」

例：
- 「我想记住一个东西一共出现了几次」→ 计数器，`++count`
- 「我想判断剩下的字节够不够读 4 个」→ `if (p + 4 > limit)`
- 「我想把一条记录加到一个列表末尾」→ `v.emplace_back(...)`

**这种问法不算"要答案"，因为逻辑还是你的，我只补那个词。**

反过来，下面这种问法帮助最小：

> 「这段怎么改？」（贴一段代码）

因为我不知道你卡在逻辑还是语法，只能猜。
